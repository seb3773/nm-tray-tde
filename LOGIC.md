# Business Logic and Lifecycle of nm-tray-tde

This document gathers sequence and state diagrams modeling the underlying business logic of the `nm-tray-tde` applet. These diagrams serve as a reference to ensure all scenarios (connection in progress, Wi-Fi refresh, device filtering) are correctly handled by the code.

## 1. Network Connection Lifecycle (Systray Animation)

The applet relies on a system of asynchronous states from NetworkManager to determine whether it should animate the system tray icon.

```mermaid
stateDiagram-v2
    [*] --> DISCONNECTED

    state "Activity Detection" as Activity {
        DISCONNECTED --> NM_STATE_CONNECTING : Connection starts
        NM_STATE_CONNECTING --> ACTIVATING : Profile activation
    }

    state "Device Verification (isRelevantDevice)" as Validation {
        ACTIVATING --> DEVICE_SOFTWARE : Software device (veth, docker0, virbr0)
        ACTIVATING --> DEVICE_HARDWARE : Hardware device (wlan0, eth0)
    }

    DEVICE_SOFTWARE --> IGNORED : Filtered out by the applet
    IGNORED --> DISCONNECTED : No animation

    DEVICE_HARDWARE --> TRAY_ANIMATING : isTrayConnecting() == TRUE
    TRAY_ANIMATING --> CONNECTED : Connection successful (IP acquired)
    TRAY_ANIMATING --> DISCONNECTED : Failure / Timeout
    
    CONNECTED --> [*]
```

### Animation Rules
- **isTrayConnecting()** evaluates whether the NM *Global State* is in `CONNECTING`, **OR** if a hardware connection (`anyActivatingConnection`) is in the activation phase, **OR** if a hardware device (`anyDeviceConnecting`) is currently being configured.
- Virtual interfaces (such as those generated by Docker/Libvirt) are strictly ignored to prevent an endless DHCP configuration of a container from locking the applet in a "Connecting" state.

## 2. Wi-Fi Scan Strategy (Hybrid)

The applet implements a hybrid Wi-Fi scan strategy inspired by `nmcli`, combined with a persistent cache to ensure instant menu opening.

```mermaid
sequenceDiagram
    actor User
    participant TrayController
    participant NmTrayPopup
    participant NmData
    participant NetworkManager (DBus)

    User->>TrayController: Left click on the icon
    TrayController->>NmData: startWifiScanOnMenuOpen()
    
    alt List already cached (Instant)
        NmData-->>TrayController: Previous SSIDs + freshness OK
        TrayController->>NmTrayPopup: show() with cached networks
    else Empty list or stale cache (> 30s)
        NmData->>NetworkManager: RequestScan() (Asynchronous)
        TrayController->>NmTrayPopup: show() with temporary list
        TrayController->>TrayController: startScanPollingIfNeeded() (Timer)
    end

    loop Polling (every 200ms)
        TrayController->>NmData: onWifiScanPoll()
        NmData->>NetworkManager: Check LastScan / New APs
        alt New networks found
            NetworkManager-->>NmData: notify::access-points
            NmData->>TrayController: changed()
            TrayController->>NmTrayPopup: rebuild() (Update UI)
        end
    end

    TrayController->>TrayController: Stop Polling after 15s or completed scan
```

## 3. Existing Wi-Fi Profile Activation

When a user clicks on a Wi-Fi network in the menu to connect to it, the applet handles deactivating concurrent connections and initiates the activation.

```mermaid
sequenceDiagram
    actor User
    participant NmTrayPopup
    participant TrayController
    participant NmData
    participant NetworkManager (DBus)

    User->>NmTrayPopup: Click on an SSID (e.g., "MyNetwork")
    NmTrayPopup->>TrayController: onConnectWifiAvailable(id)
    TrayController->>NmData: activateItem(NmItem)

    NmData->>NetworkManager: Retrieve profile (Connection UUID)
    
    alt Unknown profile
        NmData->>TrayController: Error / Password prompt (Later phase)
    else Existing profile
        NmData->>NetworkManager: ActivateConnection(Profile)
        NetworkManager-->>NmData: Activation initiated
        
        loop Listening to DBus signals
            NetworkManager-->>NmData: State -> PREPARE
            NmData->>TrayController: updateTrayState()
            TrayController->>TrayController: startConnectingAnimation()
            
            NetworkManager-->>NmData: State -> IP_CONFIG
            NetworkManager-->>NmData: State -> ACTIVATED
        end
        
        NmData->>TrayController: updateTrayState()
        TrayController->>TrayController: stopConnectingAnimation()
        TrayController->>TrayController: setStatusIcon("nm-signal-100")
        TrayController->>NmNotifier: "Connected to MyNetwork"
    end
```

## 4. Menu Refresh Logic (Fingerprint)

To prevent the open menu from "flickering" or unexpectedly closing when the Wi-Fi signal strength fluctuates, the applet uses a fingerprinting system.

```mermaid
flowchart TD
    A[NM Signal: AP state change] --> B["NmData::refresh()"]
    B --> C["TrayController::scheduleMainMenuUpdate()"]
    C --> D{"Is the menu open?"}
    
    D -- No --> E[End]
    D -- Yes --> F["TrayController::onMainMenuUpdateTimeout()"]
    
    F --> G{"Is the Saved Networks submenu open?"}
    G -- Yes --> H[Defer update 100ms Timer]
    G -- No --> I[Calculate mainMenuFingerprint]
    
    I --> J{"Has the fingerprint changed?<br/>New networks, disappearance, state change"}
    
    J -- Yes --> K["NmTrayPopup::rebuild() <br/> Rebuild the entire menu"]
    J -- No --> L["NmTrayPopup::refreshWifiSignalLevels() <br/> Update signal bars in-place"]
```
